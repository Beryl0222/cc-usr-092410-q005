# 数字文化展项立项台

本仓库记录该项目已确认的领域对象、事件名称和基础校验方式，并在此之上实现**互动组件退役（component retirement）**流程，便于不同系统交换一致的数据。

## 资料范围

- `contracts/domain.schema.json`：领域事件信封、聚合类型与事件名称（对外交换契约）。
- `data/sample.json`、`data/retirement-sample.json`：本地联调样例。
- `src/`
  - `validator.js`：事件信封的最小运行时校验（与契约枚举保持一致）。
  - `event-store.js`：仅追加事件存储（内存 + JSONL 落盘），按聚合分配连续版本。
  - `projections.js`：从事件流折叠的读模型（退役案、处置动作、批次、回执、调查项、谱系）。
  - `retirement-service.js`：组件退役领域服务（命令侧全部业务规则）。
  - `domain.ts`：领域类型定义。
- `tests/`：契约、生命周期、相邻退役交错、重启续跑、回执调查、紧急阻断、谱系追溯。

记录一经接收，标识、发生时间与版本不得原地改写；更正使用新的后继事件。个人、机构及商业敏感信息仅向履行职责所需的调用方开放。

## 组件退役流程

一个互动组件版本可能同时被多个数字展项复用。学术来源撤回后，不同展项处置不同：有的立即暂停，有的更换素材/升级版本，有的因授权范围未受影响只需补充说明后继续运行。流程如下：

1. **发起**：平台发起人选定组件版本与原因（如来源撤回），形成退役案 `RETIREMENT_INITIATED`；若该版本此前被紧急阻断，自动关联阻断记录。
2. **冻结部署范围** `DEPLOYMENT_SCOPE_FROZEN`：系统拍下发起时刻各展项在役组件快照。凡在**其他退役案**中尚有未确认处置动作（含调查未结）的展项被排除并记录原因，保证“后一批退役只能处理不受前一批未确认动作影响的范围”。冻结快照不可重做、不可变。
3. **替代方案** `REPLACEMENT_SUBMITTED`：项目负责人为需要替换的展项提交替代组件/素材。
4. **双签**：学术 `SIGNED_OFF_BY_ACADEMIC` 与法务 `SIGNED_OFF_BY_LEGAL` **分别**签署，缺一不可。
5. **处置决定** `DISPOSAL_DECIDED`：双签齐备后，对每个命中展项作出 `pause`（暂停）/ `replace`（替换）/ `annotate`（补充说明后继续运行）之一。决定一经形成不得原地改写；更正须走新的后继记录。
6. **批次下发** `DISPOSAL_REQUESTED`：可选取任意已决定动作的子集成批下发。
7. **批次关闭** `DISPOSAL_BATCH_CLOSED`：固化该批“已确认 / 未完成”的部分成功快照；**未完成项保留自身进度**，可继续等待回执，不被批次关闭终结。
8. **渠道回执**：渠道先上报 `EXECUTION_RECEIPT_REPORTED`（待核，不等于成功），平台核验无误后 `EXECUTION_RECEIPT_CONFIRMED` 才定案。

### 同一回执编号上报不同执行内容

- 同编号同内容：视为重复送达，忽略，不覆盖也不重复计成功。
- 同编号不同内容：各份原始报告**全部留痕**，动作不计成功，并开立调查项 `RECEIPT_DISCREPANCY_INVESTIGATION_OPENED`——既不覆盖也不误报成功。
- 调查结论 `INVESTIGATION_RESOLVED`：`confirmed=true` 则动作以“调查确认”定案；`confirmed=false` 则动作退回待重报，渠道须以**新回执编号**重新上报。
- 若异议在动作确认之后才出现，既有确认状态不被推翻，异议作为后继调查挂账另行核查（旧的已确认执行回执不得改写）。
- 回执编号不得跨处置动作混用。

### 紧急阻断

紧急风险可先调用 `urgentBlock` 立即阻断命中的组件版本（`COMPONENT_BLOCKED_URGENTLY`），并据此立刻暂停当前上线该版本的展项。阻断只**追加**事件，不触碰任何旧发布记录与已确认执行回执。

### 重启续跑与谱系追溯

- 服务重启时从 JSONL 事件流重放重建读模型，从各展项的处置进度（待核、调查中、部分完成）原样继续。
- `trace({ exhibit_id, online_release })` 让管理者从**任一上线版本**追到：组件发布谱系与跨展项复用、证据变化（来源撤回等后继事件）、学术/法务签署决定、每展项处置决定与实际执行回执/调查。

## 关键不变量

- 事件仅追加：`event_id` 全局唯一；同一聚合 `version` 从 1 起严格连续，重放时对重号、乱序、坏信封一律拒绝。
- 冻结范围、处置决定、批次关闭、调查结论、回执确认均不可原地改写。
- 批次允许部分成功；动作状态独立推进，跨批次保留。
- 相邻退役通过“未确认动作即排除”实现范围隔离与顺序不被打乱（见 `tests/retirement-interleaving.test.js`）。

## 本地检查

```bash
npm test        # 运行全部 node:test 用例
npm run build   # 对全部 src/*.js 做语法检查
```

这些命令可在单个 Linux 应用容器内执行，不需要另行启动外部服务。
